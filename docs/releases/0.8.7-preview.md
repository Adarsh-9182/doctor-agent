# Android 0.8.7 preview — evidence retrieval regression fixes

## Changes

- Added explicit `retrieval_terms` to the six existing catalog entries. A topic match is required before a source can be selected; overlap with generic words in a summary is no longer enough.
- Added BM25 scores across title, keywords and body with field weights 3, 1.5 and 0.5; k1=1.2 and b=0.75. Explicit topics are ordered by their first mention, then competing sources are ranked by score. Repeated query words are deduplicated. Scores are retrieval diagnostics, not probabilities of medical correctness. Algorithm background: [Elastic's BM25 explanation](https://www.elastic.co/blog/practical-bm25-part-2-the-bm25-algorithm-and-its-variables).
- Vague queries such as “healthy” and “tired” ask for a supported topic. Selected phrases such as “REST API”, “license plate” and “sleep mode” do not activate unrelated health sources. This is a bounded lexical approach, not semantic understanding or a comprehensive out-of-domain classifier.
- Fixed Hindi safety normalization removing Devanagari vowel/combining marks. Added bounded aliases for balanced meals and physical activity.
- An explicitly matched new topic takes precedence over a Hindi follow-up phrase in the Android conversation wrapper.
- Added expandable source-summary views. These show the app's bundled English summaries, not verbatim quotations or fresh web retrieval. Existing citations still open the original source. The library remains six entries; no new medical claims or reviewed clinical content were added.
- Repaired the standalone Android evaluator so it compiles all required helper classes, merges localized keywords like the app, and can compare previous source/catalog revisions against current cases.

## Software evaluation

The same 50 synthetic cases passed 30/50 on 0.8.6 (commit `15967d06dc3eb07ee455f524a868028b183b54f1`) and 50/50 on this update. Results are stored in [the development regression report](https://github.com/Adarsh-9182/doctor-agent/blob/v0.8.7-preview/evals/results/android-retrieval-0.8.7.json); reproduction commands are in [the evaluation guide](https://github.com/Adarsh-9182/doctor-agent/blob/v0.8.7-preview/evals/README.md).

These cases were used to develop the fix. They are not a clinician-reviewed or independent held-out benchmark, and the scores are not evidence of superiority to GPT. They check the pure Java engine's selected cases, not the Android activity's complete conversational behavior. The dataset includes selected Hindi boundary cases but does not establish fluent-Hindi or comprehensive emergency handling.

Both Android debug APK variants compiled and were packaged. No phone/emulator runtime, accessibility, generated-model-output or clinical validation was performed for this update. Topic routing still cannot establish that a summary answers every detail of a question; the source reply now states this limitation. Prescription/diagnosis and urgent-phrase checks remain incomplete fixed-pattern boundaries. Mac, PWA and Python engines have not received the Android ranking change.
