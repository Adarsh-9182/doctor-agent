# Android 0.8.6 preview — optional encrypted chat history

## Changes

- Added Save and Update for explicit conversation snapshots, plus History and New in Chat.
- Saved messages retain their source links and AI-draft labels. The unsent draft is excluded. New messages are not automatically saved: tap Update to replace the snapshot.
- History supports reopening a conversation, renaming its title, deleting one saved copy and deleting all saved copies. Opening another chat or starting a new one asks before replacing a session with user messages or an unsent draft.
- Saved snapshots use a separate Android Keystore key and AES-GCM through the existing atomic storage helper. The encrypted file lives in private no-backup storage. Chat snapshots are not synced or exported.
- Storage is limited to 20 chats, 80 messages per snapshot and 2 MiB total plaintext. Older saved chats are not silently evicted; the user deletes one explicitly when needed. A storage/decryption failure leaves existing data untouched and exposes a reset action.
- Source summaries and URLs remain snapshots of what was shown, not updated evidence. Reopened source answers can support follow-ups in that conversation. The existing opt-in still controls whether bounded recent exchanges are included in a local AI request; other saved chats are not searched or automatically supplied to the model.
- Fixed read-aloud button cleanup when the oldest message is trimmed, and skipped per-message animation when replaying a retained or saved chat.

## Validation limits

Both Android debug APK variants compiled and were packaged. No automated tests or device runtime checks were run for this release; product testing remains deferred. Save/reopen, deletion, rotation, process recreation, storage-error handling and Android Keystore behavior still require device verification. This feature does not expand medical knowledge or establish clinical safety. The Mac app and PWA do not yet have this history feature.
