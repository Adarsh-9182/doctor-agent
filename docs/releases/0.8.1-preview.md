# Android 0.8.1 preview — local model compatibility

## Changes

- Fixed the pinned Qwen3 starter model's embedded chat-template incompatibility with LiteRT-LM 0.18.0. The error was `string and sequence` during message rendering, after engine initialization succeeded.
- Added a text-only Qwen ChatML adapter, selected only after matching the starter model's size and SHA-256. Other imported models keep their own templates.
- Added separate model-loading and generation status messages, memory/runtime failure messages, and an explicit 60-second timeout message.
- Diagnostic logs contain only the failure phase and exception class, never chat text or personal context. Temporary exception logging used for the synthetic reproduction was removed.
- Android companion build and install scripts now read the version from Gradle instead of hardcoding the old APK filename.
- Strengthened the prompt against inventing causes or relationships absent from source summaries.

## Runtime evidence and limits

The compatibility build generated a local AI draft for the synthetic question `sleep` in the existing ARM64 Android API 37 emulator on this Mac. The source answer remained available. This establishes that the template failure was resolved on that emulator, not that all imported models or physical phones work.

The draft also contained an unsupported inference. The added grounding instruction is a mitigation, not evidence of medical correctness. Outputs remain explicitly unverified. No clinical validation, multilingual safety evaluation, physical-phone performance measurements, or broader test suite was performed for this change.
